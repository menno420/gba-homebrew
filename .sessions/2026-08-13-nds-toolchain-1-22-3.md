## Migration-test verdict (2026-08-14, measured)

The mirror works (all 8 packages fetch + hash-verify; toolchain installs in
CI and locally) and **all games compile clean under 1.22.3** — but the
runtime harness caught real behaviour drift, so this card stays
`in-progress` and nothing merges on it yet:

- **Gloamline**: boots, renders, plays; one pin shifted — the run seed
  (`t[12]`, = frame counter latched at the scripted START press) reads 119
  vs the pinned 118: one frame of boot-latency shift.
- **Brineward**: the same +1 latch shift, propagated — 10 of 18 pins moved
  by one world-frame's worth (positions at pinned emulator frames read one
  frame behind the old values).
- **Underroot: genuine half-rate regression.** Local diagnostic under the
  same py-desmume harness, sampling `t[2]` (per-vblank frame counter):
  74@150 · 124@250 · 174@350 · 249@500 — slope exactly 0.5 from boot.
  Both games use the identical single-`swiWaitForVBlank()` loop, so this is
  a game-workload × libnds-1.22 timing interaction, upstream cause
  undiagnosed. Not a golden to re-pin — the game genuinely runs at half
  speed under this SDK in the emulator.

Also measured en route: the exact 1.21.1 bytes are unrecoverable — Wayback
now answers definitively (`archived_snapshots: {}`), joining the upstream
404s, the version-less mirrors, the artifact-less upstream repo, and the
evicted Actions cache. Codex R1 (P3): active docs still describe 1.21.1 and
"no mirror needed" (BUILDING.md, current-state.md, PLAYING-BRINEWARD.md,
this script's old NOTE) — owed to whichever path completes this PR.
